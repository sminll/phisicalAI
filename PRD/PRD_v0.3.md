# PRD: AI 분리수거 도우미 스마트 쓰레기통 (v0.3)

- 작성자: 이수민
- 작성일: 2026-10-08
- 버전: v0.3 (v0.2 대비 현장 조사 결과·전처리 보고서 반영, 서버·DB·대시보드·알림 추가, ROI 정량 분석 추가)
- 관련 문서: report/checklist.md (현장 조사), report/preprocess.md (전처리), code/preprocess_code.py (구현)

**제품명**: AI 분리수거 도우미 스마트 쓰레기통

**주요 입력 데이터**
- 카메라 영상: 쓰레기통 윗면 USB 웹캠(1280×720)으로 위에서 아래로 촬영한 RGB 이미지 (회색 배경판 위, 손에 든 쓰레기)
- 근접 센서 값: 초음파 센서(HC-SR04)의 거리 값으로 물체 접근을 감지해 촬영 시점 결정
- 적재량 센서 값: 투입구별 초음파 센서로 측정한 쓰레기 높이 (v0.3 추가)

**주요 출력(행동)**
- 분류 결과: 페트병 / 캔 / 일반쓰레기 / 물체 없음 중 하나와 신뢰도
- 투입구 안내: 해당 투입구 LED 점등 + 서보모터로 뚜껑 자동 열림 (약 5초 후 닫힘)
- 재시도 안내: 신뢰도 0.7 미만 또는 흔들림 시 노란 LED 점멸 (최대 2회), 이후 실패 시 일반쓰레기 투입구 안내
- 결과 기록·전송: 시간·분류 결과·신뢰도·처리 시간을 텍스트로 저장하고 관리자 서버로 전송 (이미지는 저장·전송하지 않음)
- 관리자 알림: 적재량 80% 초과, 장치 오프라인, 인식 품질 저하 시 알림 발송

## 1. 문제 정의 (Problem Statement)

### 현재 문제

학교·공공시설의 분리배출함에서 페트병, 캔, 일반쓰레기가 섞여 버려지는 일이 반복된다. 설치 후보 장소(본관 2층 매점 옆 복도) 조사 결과, 이용자는 라벨이 붙은 채 찌그러지고 내용물이 남은 페트병을 그대로 버리고, 매점 아이스음료 플라스틱 컵과 은박 과자 봉지처럼 재질을 헷갈리기 쉬운 쓰레기가 많았다. 점심시간에는 10분에 30명 이상이 몰려 이용자가 분류를 고민할 시간이 거의 없다.

혼입된 재활용품은 시설 관리 인력이 다시 선별해야 하며, 선별되지 못한 재활용품은 일반쓰레기로 소각·매립된다. 조사 장소 기준 재활용 칸 혼입률은 약 30~40% 수준으로 추정되며(가정), 관리 인력은 10개 분리배출 지점에 대해 하루 약 2시간을 재선별에 쓰고 있다(가정).

### 기존 방식의 한계

- **안내문·스티커**: 이용자가 읽고 판단해야 하므로 급한 상황에서는 무시된다. 한글 안내문은 외국인 방문객에게 효과가 없다.
- **사후 재선별**: 문제가 생긴 뒤에 사람이 처리하는 방식이라 인건비가 계속 발생하고, 오염된 재활용품은 이미 재활용이 어렵다.
- **단일 센서 기반 자동 분류함**: 금속 감지 센서는 캔만 구분할 수 있고, 무게 센서는 빈 페트병·플라스틱 컵·종이컵의 무게가 비슷해 구분하지 못한다. 바코드 방식은 라벨이 없거나 찌그러진 용기에서 실패한다.
- **고가 상용 순환자원 회수기**: 대당 수백만 원 이상으로(가정) 복도마다 설치하기 어렵고, 투입구가 하나라 일반쓰레기와 함께 쓰는 분리배출함 용도에 맞지 않는다.

### 핵심 가치

쓰레기를 버리는 **바로 그 순간**에, 이용자가 아무것도 읽거나 누르지 않아도 올바른 투입구를 불빛과 열리는 뚜껑으로 알려준다. 이를 통해 혼입률을 낮추고 관리자의 재선별 시간을 줄이며, 관리자는 대시보드로 장소별 투입 현황과 적재 상태를 원격으로 확인한다.

### 왜 AI가 필요한가

투명 페트병, 투명 플라스틱 컵, 은색 캔, 은박 봉지는 무게·금속 여부·색만으로는 구분되지 않고 **모양과 질감**을 함께 봐야 구분된다. 찌그러짐, 라벨 유무, 손에 가려지는 정도, 조명 변화까지 고려하면 규칙 기반 영상 처리로는 대응할 경우의 수가 너무 많다. 이미지 분류 딥러닝 모델(MobileNetV3)은 이런 변형을 학습 데이터와 증강으로 흡수할 수 있고, INT8 양자화 시 Raspberry Pi에서 1장당 수십~수백 ms로 추론할 수 있어 2초 안내 목표를 저가 하드웨어로 달성할 수 있다.

## 2. 사용자 시나리오 (User Scenario)

등장 사용자는 **시설 관리자**(설치·운영)와 **이용자**(학생·방문객) 두 유형이다.

### 1단계: 사용자가 제품을 설치한다

관리자가 기존 3구 분리배출함 위치에 제품을 놓고 전원과 학교 내부 Wi-Fi를 연결한다. 설치 앱 없이 제품 내부의 설치 모드를 실행하면 카메라 화면에서 배경판 영역(ROI)을 확인하고, 자동 노출·화이트밸런스를 고정한 뒤, 관리 서버에 장치 ID와 설치 위치(예: 본관 2층 매점 옆)가 등록된다. 설치 소요 시간은 대당 2시간 이내를 목표로 한다.

### 2단계: AI가 데이터를 수집한다

이용자가 쓰레기를 들고 다가오면 접근용 초음파 센서가 약 25cm 이내의 물체를 감지하고(가정), Arduino가 Raspberry Pi에 감지 신호를 보낸다. Pi는 카메라 버퍼의 오래된 프레임을 버린 뒤 5장을 연속 촬영한다. 이와 별도로 투입구별 적재량 센서가 10분마다 적재 높이를 측정한다.

### 3단계: AI가 분석을 수행한다

5장 중 가장 선명한 프레임(Laplacian 분산 최대)을 고르고, ROI 크롭 → 224×224 리사이즈 → 정규화를 거쳐 MobileNetV3 INT8 모델로 추론한다. 모든 처리는 Pi 내부에서 오프라인으로 이루어지며, 원본 프레임은 추론 직후 메모리에서 삭제된다.

### 4단계: 판단 결과를 생성한다

모델은 페트병·캔·일반쓰레기·물체 없음의 확률을 출력하고, 후처리 규칙으로 최종 판단을 내린다.

- 물체 없음으로 판정되면 재시도하고, 3회 모두 물체 없음이면 오감지(지나가는 사람 등)로 보고 뚜껑을 열지 않고 취소한다.
- 물체는 있지만 선명도가 기준 미만이거나 신뢰도가 0.7 미만이면 재시도한다(최대 2회).
- 재시도 후에도 판별하지 못하면 일반쓰레기를 안전한 기본값으로 안내한다.

### 5단계: 제품이 사용자 또는 주변 장치를 제어한다

Pi가 Arduino로 명령을 보내면 해당 투입구의 LED가 켜지고 서보모터가 뚜껑을 연다. 재시도가 필요하면 노란 LED가 점멸한다. 동시에 분류 결과 텍스트(시간, 결과, 신뢰도, 시도 횟수, 처리 시간)를 Pi의 로컬 DB에 저장하고 MQTT로 관리 서버에 전송한다. 네트워크가 끊겨도 안내 동작은 그대로 수행되며, 저장된 기록은 연결이 복구되면 재전송된다.

### 6단계: 사용자가 결과를 확인하고 후속 행동을 수행한다

이용자는 켜진 투입구에 쓰레기를 넣는다. 관리자는 대시보드에서 장소별 투입량, 품목 비율, 재시도·폴백 비율, 적재 상태를 확인하고, "적재 80% 초과" 알림을 받으면 해당 투입구를 수거한다. 주간 리포트에서 폴백 비율이 높은 장소나 시간대가 보이면 현장 사진을 추가 수집해 모델을 재학습하거나 안내 위치·조명을 조정한다.

## 3. 성공 지표 (Success Metrics)

### AI 성능 KPI (개발 완료 기준)

- **분류 정확도 90% 이상**: 설치 장소에서 촬영한 테스트셋(클래스별 30장 이상, 총 120장 이상, 학습과 다른 날짜·시간대 세션)으로 측정한다.
- **클래스별 최저 정확도 85% 이상**: 데이터가 가장 적은 캔 클래스와 혼동이 잦은 플라스틱 컵·은박 봉지를 포함해 측정한다.
- **응답 시간 2초 이내 (95백분위 기준)**: 감지 신호 수신부터 LED 점등까지를 장치 로그로 측정한다. 평균 목표는 1초 이내.
- **오감지 개방률 1% 이하**: 물체 없이 사람만 지나간 경우 뚜껑이 열린 비율.
- **INT8 양자화 후 정확도 하락 2%p 이하**, 모델 파일 10MB 이하.

### 장치·시스템 KPI (시범 운영 4주 기준)

- **장치 동작 성공률 95% 이상**: LED·서보 100회 반복 시험 중 정상 동작 비율.
- **장치 가동률 98% 이상**: 운영 시간 중 대시보드에서 온라인으로 확인된 시간 비율(가정).
- **데이터 전송 성공률 99% 이상**: 장치에 기록된 이벤트 중 서버에 도달한 비율(재전송 포함).
- **적재 알림 정확도 90% 이상**: 알림 발생 시 실제 적재율이 70% 이상이었던 비율.

### 현장 효과 KPI (시범 운영 4주 기준)

- **혼입률 50% 이상 감소**: 설치 전 1주와 설치 후 1주의 투입물 샘플 검사 비교.
- **재선별 시간 50% 이상 감소**: 관리자 작업 일지 기준.
- **첫 사용 성공률 80% 이상**: 설명 없이 처음 사용한 이용자가 올바른 칸에 넣은 비율(관찰).
- **재시도 발생률 15% 이하, 폴백(일반쓰레기 기본 안내) 비율 5% 이하**: 장치 로그 기준. 이 수치가 오르면 모델 성능 저하 신호로 본다.
- **이용자 만족도 5점 만점 4점 이상**: 이용자 30명 이상 설문.

## 4. 기술 스택 (Technology Stack)

| 구성 | 사용 기술 | 선정 이유 |
|---|---|---|
| 카메라 | USB 웹캠 720p (UVC 호환), 상단 하향 설치 | 저가·드라이버 불필요, V4L2로 노출·화이트밸런스 수동 고정 가능 |
| 보조 광학 | 차광 후드 + 확산형 LED 조명 + 무광 회색 배경판 | 창가 역광·시간대별 밝기 변화를 하드웨어로 차단 (조사 결과 최대 위험 요소) |
| 센서 (접근 감지) | 초음파 센서 HC-SR04 | 저가·검증된 부품, 감지 시에만 촬영해 불필요한 추론과 오작동 감소 |
| 센서 (적재량) | 투입구별 초음파 센서 HC-SR04 3개 | 수거 시점 알림용, 접근 센서와 같은 부품으로 재고·유지보수 단순화 |
| MCU | Arduino Uno (ATmega328P) | LED·서보·센서의 실시간 제어를 Pi와 분리해 Pi 지연이 뚜껑 동작에 영향을 주지 않음 |
| Edge AI 장치 | Raspberry Pi 4 (4GB), Raspberry Pi OS 64-bit | 온디바이스 추론으로 오프라인 동작·영상 외부 유출 없음, 교육·산업 현장 레퍼런스 풍부 |
| AI 모델 | MobileNetV3-Small 이미지 분류 (4클래스, ImageNet 전이학습) | 경량·Pi에서 빠름, Apache 2.0 라이선스로 상용화 시 라이선스 비용 없음 (YOLOv8은 AGPL-3.0이라 상용 시 별도 라이선스 필요) |
| 추론 런타임 | TensorFlow Lite INT8 (ai-edge-litert) | 양자화로 모델 크기·추론 시간 감소, Pi용 공식 지원 |
| 학습 환경 | Google Colab (GPU), TensorFlow/Keras | 초기 비용 없이 GPU 학습, 재학습 절차를 노트북으로 표준화 |
| 영상 전처리 | OpenCV, albumentations, imagehash | 품질 필터·ROI·증강·중복 제거의 업계 표준 라이브러리 |
| 장치 제어 통신 | USB 시리얼 (115200bps, 1문자 명령 프로토콜) | 단순·지연 낮음, 디버깅 용이 |
| 장치-서버 통신 | MQTT (Mosquitto 브로커, QoS 1), 학교 내부 Wi-Fi | IoT 표준, 저대역·끊김에 강하고 메시지 재전송 보장 |
| 로컬 저장 | SQLite (장치 내부 버퍼) | 네트워크 단절 시에도 기록 유지, 복구 후 재전송 |
| 서버 | 교내 미니 PC 1대 (Ubuntu Server, Docker Compose) | 데이터를 학교 밖으로 내보내지 않음, 클라우드 비용 없음 |
| 데이터베이스 | PostgreSQL | 이벤트 시계열 집계·장소별 통계 쿼리에 충분, 운영 레퍼런스 풍부 |
| 대시보드 | Grafana | 코드 없이 시계열 대시보드 구성, 산업 모니터링 표준 도구 |
| 알림 시스템 | Grafana Alerting → 텔레그램 봇 + 이메일 | 별도 앱 개발 없이 관리자 휴대폰으로 즉시 알림 |
| 장치 운영 | systemd 서비스 + 워치독 재시작 | 전원 재투입·오류 시 자동 복구로 가동률 확보 |
| 개발 언어 | Python (AI·전처리·서버 연동), C++ (Arduino 펌웨어) | 팀 역량과 라이브러리 생태계 |

## 5. 개발 범위 / 비범위 (Scope)

### 개발 범위 (In Scope)

- **[P0] 실시간 쓰레기 인식**: 접근 감지 시 5프레임 촬영, 최선 프레임 선택, 페트병·캔·일반쓰레기·물체 없음 4클래스 분류와 신뢰도 산출. 응답 2초 이내.
- **[P0] 장치 제어**: 투입구별 RGB LED 점등과 서보모터 뚜껑 개폐, 재시도 시 노란 LED 점멸.
- **[P0] 판단 후처리 규칙**: 신뢰도 0.7 기준, 최대 2회 재시도, 물체 없음 3회 시 취소, 판별 실패 시 일반쓰레기 안내.
- **[P0] 프라이버시 보호**: 영상·이미지를 저장·전송하지 않고 추론 직후 메모리에서 삭제, 상단 촬영으로 얼굴 촬영 최소화.
- **[P1] 학습 데이터 파이프라인**: 얼굴 필터, 품질 필터, 중복 제거, 라벨 검수 목록, 세션 단위 분할, 증강, INT8 변환 (code/trash_pipeline.py).
- **[P1] 로그 저장**: 장치 내부 SQLite에 이벤트(시간, 결과, 신뢰도, 시도 횟수, 처리 시간, 선명도) 저장.
- **[P1] 적재량 감지**: 투입구별 적재율 10분 주기 측정.
- **[P2] 데이터 전송·저장**: MQTT로 서버 전송, PostgreSQL 저장, 네트워크 복구 시 재전송.
- **[P2] 관리자 대시보드**: 장소별 투입량, 품목 비율, 재시도·폴백 비율, 응답 시간, 적재 상태, 장치 온라인 여부.
- **[P2] 알림 기능**: 적재 80% 초과, 장치 10분 이상 오프라인, 폴백 비율 일 10% 초과(렌즈 오염·조명 이상 신호) 시 텔레그램·이메일 알림.

### 개발 제외 범위 (Out of Scope)

- **음식물·이물질 오염 여부 판단**: 내용물 감지는 추가 센서와 대규모 데이터가 필요해 제외. 내용물이 남은 용기도 형태로만 분류한다.
- **분류 품목 확장 (종이, 비닐, 유리, 플라스틱 컵 별도 분류)**: 1차 버전은 4클래스 정확도 확보에 집중. 플라스틱 컵 등 경계 품목은 학교 배출 기준에 따라 기존 클래스 중 하나로 라벨링한다.
- **자동 투입·분류 기계 장치**: 컨베이어·분류 플랩 없이 안내형으로 한정하며 투입은 이용자가 한다.
- **이용자 식별 및 개인별 기록·보상**: 프라이버시 보호를 위해 얼굴·학생증 인식, 포인트 적립을 하지 않는다.
- **클라우드 학습 및 원격 자동 모델 배포(OTA)**: 재학습은 Colab에서 수동으로 하고 모델 교체는 관리자가 직접 수행한다.
- **모바일 앱 개발**: 관리자 기능은 웹 대시보드와 메신저 알림으로 대체한다.
- **음성 안내 및 다국어 지원**: 색·불빛·뚜껑 동작만으로 언어 없이 안내한다.
- **지자체·외부 수거업체 시스템 연동**: 외부 네트워크 연결과 보안 요구사항이 커서 제외한다.

- 장비 1대 제품화 원가: 192,000원 (Pi 4 세트, 웹캠, Arduino, 서보 3, LED, 초음파 센서 4, 조명·차광 후드·배경판, 외함 개조 포함) (가정)

### 최종 판정

**10대 단일 학교 도입: 조건부 승인 (시범 운영 권장)**
투자 회수기간 약 35개월로, 장비 기대 수명 3~5년(가정) 안에 회수는 가능하지만 여유가 작다. 혼입률 감소 효과가 50%가 아닌 30%에 그치면 월 절감액이 약 292,000원으로 줄어 회수기간이 약 94개월로 늘어나므로, 재무 효과만으로 단일 학교 도입을 확정하기는 어렵다.

**30대 이상 확대 도입: 투자 타당**
AI 모델 개발비 3,000,000원은 1회성이라 설치 대수가 늘수록 대당 부담이 작아지고, 재학습 공수도 대수와 무관하게 고정된다. 30대 기준 회수기간 15.5개월, 연간 ROI 77.4%로 일반적인 설비 투자 기준(회수 24개월 이내)을 충족한다.

**권고 실행 순서**
1. 1개 학교 10대로 4주 시범 운영을 하며 혼입률·재선별 시간 감소를 실측한다.
2. 혼입률 40% 이상 감소가 확인되면 30대 이상으로 확대한다.
3. 재무 효과 외에 분리배출 교육 효과, 학교 ESG·환경교육 성과 자료로 활용할 수 있다는 점을 정성적 가치로 함께 보고한다.

> 참고: 학교 수업 프로젝트로 진행하는 경우 개발비(3,000,000원)와 설치 공수가 인건비로 발생하지 않고 기존 Pi·Arduino 키트를 활용할 수 있어, 실제 회수기간은 위 계산보다 크게 짧아진다.
