## 1. 결론 요약

이 제품에는 **YOLO26n 객체 검출(detect) 모델을 COCO 사전학습 가중치에서 시작해 전이학습**하는 방식이 가장 적합하다.

입력 크기는 320으로 시작해 416과 비교하고, Raspberry Pi 4에는 NCNN 형식으로 변환해 배포한다. 학습은 현장에서 촬영한 사진을 세션(날짜·시간대) 단위로 나눈 데이터로 진행하고, 검증은 모델 지표(mAP·정밀도·재현율)와 제품 지표(최종 안내 정확도·응답 시간·오감지율)를 두 단계로 나눠서 한다.

핵심 이유는 세 가지다. 현장 조사에서 2~3개를 한꺼번에 보여주는 경우가 관찰되었는데, 검출 모델은 물체 개수를 셀 수 있어 "하나씩 보여주세요" 안내를 구현할 수 있다. nano 크기라 Pi 4에서도 2초 목표를 맞출 수 있다. 그리고 데이터가 클래스당 200~500장으로 적기 때문에 사전학습 가중치 없이는 정확도 90%를 기대하기 어렵다.

## 2. 제품 조건 정리 (모델 선정 기준)

모델은 아래 조건을 모두 만족해야 한다. 각 조건의 출처는 PRD v0.3과 현장 조사 결과(S-01)다.

분류 대상은 페트병, 캔, 일반쓰레기 3종이며 전체 정확도 90% 이상, 클래스별 최저 85% 이상이 목표다. 물체를 보여준 뒤 안내까지 2초 이내(95백분위 기준)여야 하고, 모델 파일은 10MB 이하로 Raspberry Pi 4(4GB)에서 인터넷 없이 동작해야 한다.

현장 조건으로는 카메라가 20~40cm 위에서 아래로 찍기 때문에 쓰레기가 화면에서 크게 보이고, 손이 거의 항상 함께 찍힌다. 점심시간에는 이용자가 몰리고 친구 것까지 2~3개를 한꺼번에 보여주는 경우가 15분에 5번 정도 있었다. 캔은 전체의 15%로 데이터가 가장 적고, 매점 플라스틱 컵과 은박 과자 봉지가 헷갈리는 물체로 지목되었다.

## 3. YOLO 모델 후보와 선정 이유

### 3.1 YOLO 모델 종류 한눈에 보기

YOLO 모델은 **버전(세대)**, **크기**, **작업 종류** 세 가지 기준으로 나뉘며, 모델 이름에 이 세 가지가 모두 들어 있다. 예를 들어 yolo26n은 "26세대 · nano 크기 · 검출용", yolo26s-cls는 "26세대 · small 크기 · 분류용"이라는 뜻이다.

#### 버전(세대)

YOLO는 "사진을 한 번만 보고(You Only Look Once) 물체를 찾는다"는 아이디어로 2015년에 처음 발표된 뒤, 여러 연구팀과 회사가 계속 새 버전을 내놓았다.

YOLOv1~v3(2015~2018)는 YOLO를 처음 만든 연구자 Joseph Redmon이 발표한 초기 버전이다. YOLOv4~v7(2020~2022)은 여러 연구팀이 각자 개량한 버전으로, 이 중 Ultralytics 사가 만든 v5가 사용법이 쉬워 교육과 현업에서 널리 쓰였다. YOLOv8(2023)은 Ultralytics 버전으로 검출·분류·분할을 하나의 도구에서 같은 명령어로 할 수 있게 했다. 이후 YOLOv9, v10, YOLO11, v12(2024~2025)가 이어졌으며, v10은 겹친 박스를 지우는 후처리(NMS) 없이 동작하는 방식을 본격적으로 도입했다. YOLO26은 Ultralytics의 최신 세대로, NMS 없이 동작하는 구조와 엣지 장치 최적화가 특징이다.

버전마다 만든 팀이 달라 사용법이 다를 수 있다. 이 프로젝트에서 사용하는 Ultralytics 도구로는 v5, v8, 11, 26 등을 같은 명령어로 학습·검증·변환할 수 있어 버전 간 비교가 쉽다. 버전별 정확한 출시 시기와 성능 수치는 Ultralytics 공식 문서에서 최신 내용을 확인한다.

#### 크기

같은 버전 안에서도 모델 크기가 5단계로 나뉜다. 크기가 클수록 모델 내부의 층과 계산량이 많아져 정확도는 오르지만, 속도가 느려지고 모델 파일과 메모리 사용량이 커진다.

n(nano)은 가장 작고 빠른 모델로, Raspberry Pi나 스마트폰처럼 GPU가 없거나 약한 소형 장치에 적합하다. s(small)는 nano보다 조금 크고 정확한 모델로, 소형 장치에서 nano의 정확도가 부족할 때나 노트북 CPU 환경에서 쓴다. m(medium)은 정확도와 속도의 균형형으로, Jetson 같은 GPU 탑재 엣지 장치나 일반 PC GPU에서 실시간 처리에 쓴다. l(large)과 x(extra large)는 가장 크고 정확한 모델로, 서버 GPU에서 속도보다 정확도가 중요할 때 쓴다.

정리하면 장치 성능이 낮을수록 작은 모델을, 정확도 요구가 높고 장치가 강력할수록 큰 모델을 고른다. 같은 크기 이름이라도 버전이 올라가면 대체로 같은 속도에서 정확도가 개선된다.

#### 작업 종류

모델 이름 끝에 붙는 이름으로 어떤 작업을 하는 모델인지 구분한다.

검출(detect, 이름 끝에 아무것도 없음)은 물체마다 박스를 치고 클래스를 붙인다. 분류(classify, -cls)는 사진 전체를 보고 하나의 클래스만 답한다. 분할(segment, -seg)은 박스 대신 물체의 모양을 픽셀 단위로 칠한다. 자세 추정(pose, -pose)은 사람의 관절 위치를 찾는다. 회전 박스(obb, -obb)는 항공 사진 속 배처럼 기울어진 물체에 비스듬한 박스를 친다.

#### 이 제품의 위치

이 제품은 Raspberry Pi 4의 CPU에서 2초 안에 판단해야 하고(크기: nano), 여러 개를 한꺼번에 보여주는 경우를 구분해야 하므로(작업: 검출), 엣지 장치에 최적화된 최신 세대(버전: 26)인 **yolo26n**을 기본 모델로 한다. 각 선택의 자세한 근거는 3.2~3.5절에 정리했다.

### 3.2 YOLO 버전: YOLO26

Ultralytics의 최신 세대인 YOLO26을 기본으로 한다. YOLO26은 엣지 장치 배포를 목표로 설계되어, 추론 결과에서 겹친 박스를 지우는 후처리(NMS) 없이 바로 결과를 내는 구조이고, CPU 추론 속도를 이전 세대보다 크게 개선한 것으로 소개되어 있다. Raspberry Pi 4는 GPU 가속이 없어 CPU로만 추론하므로 이 특징이 그대로 이점이 된다.

YOLO26에서 변환(export)이나 Pi 실행 중 문제가 생기면 이전 세대인 YOLO11n을 대안으로 쓴다. 두 모델은 같은 Ultralytics 명령어로 학습·검증할 수 있어서 비교와 교체가 쉽다.

세부 성능 수치는 버전 업데이트에 따라 바뀔 수 있으므로, 최종 선정 전 Ultralytics 공식 문서(docs.ultralytics.com)의 최신 표와 아래 7장의 실측 결과로 확인한다.

### 3.3 작업 유형: 분류(cls)가 아니라 검출(detect)

YOLO에는 이미지 전체를 한 클래스로 판정하는 분류 모델(yolo26n-cls)과, 물체마다 박스와 클래스를 찾는 검출 모델(yolo26n)이 있다.

분류 모델은 라벨링이 쉽고 빠르지만, 사진에 쓰레기가 2개 있어도 하나의 답만 내기 때문에 "여러 개"를 구분하지 못한다. 그러면 PRD의 예외 시나리오인 "하나씩 보여주세요"를 지킬 수 없다. 또 빈 화면을 처리하려면 "물체 없음" 클래스를 따로 학습시켜야 한다.

검출 모델은 박스 개수로 여러 개를 바로 알 수 있고, 박스가 하나도 없으면 그 자체가 "물체 없음"이라 별도 클래스가 필요 없다. 손이 함께 찍혀도 쓰레기 영역에 박스를 치므로 손이나 배경의 영향을 덜 받는다. 대신 사진마다 박스를 그려야 해서 라벨링 시간이 늘어나는데, 이 비용보다 여러 개 처리와 오감지 감소의 이점이 크다고 판단했다.

따라서 클래스는 pet, can, general 3개로 정의하고, 기존의 "none" 클래스는 "박스 없음"으로 대체한다.

### 3.4 모델 크기: nano(n)

YOLO 모델은 n(nano), s(small), m, l, x 순으로 커진다. 크기가 커질수록 정확도는 오르지만 속도가 느려진다.

이 제품은 쓰레기가 화면을 크게 차지하고 클래스가 3개뿐이라 어려운 문제가 아니다. 반면 Pi 4의 CPU에서 2초 안에 촬영 5장, 선명도 계산, 추론, Arduino 전송까지 끝내야 한다. 따라서 nano를 기본으로 하고, nano가 정확도 기준을 못 넘으면 small을 비교 후보로 둔다. nano 모델 파일은 수 MB 수준이라 10MB 제한도 여유 있게 만족한다.

### 3.5 입력 크기: 320에서 시작

YOLO 기본 입력 크기는 640이지만, 이 제품은 카메라와 물체 거리가 20~40cm로 가까워서 쓰레기가 화면의 상당 부분을 차지한다. 작은 물체를 찾을 필요가 없으므로 입력을 320으로 줄여 연산량을 약 4분의 1로 줄인다. 320과 416을 모두 학습해 정확도와 Pi 속도를 비교한 뒤 결정한다.

### 3.6 라이선스 확인

Ultralytics YOLO는 AGPL-3.0 라이선스다. 지금처럼 학교 프로젝트로 코드를 공개 저장소에 올려 쓰는 것은 문제가 없다. 다만 이 제품을 판매하는 등 상용화할 때는 소스 공개 의무가 생기므로 Ultralytics Enterprise 라이선스를 구매하거나, PRD v0.3에서 검토한 Apache 2.0 라이선스의 MobileNetV3로 바꿔야 한다. 이 점은 PRD의 기술 스택과 ROI(라이선스 비용 0원 가정)에 반영해야 한다.

## 4. 사전학습 모델을 사용하는 이유

사전학습 모델을 사용한다. 정확히는 COCO 데이터셋으로 미리 학습된 yolo26n.pt 가중치에서 출발해, 우리 쓰레기 사진으로 다시 학습하는 **전이학습(Transfer Learning)** 방식이다.

첫째, 데이터가 적다. 현장 조사 기준 클래스당 200~500장을 모을 예정인데, 처음부터(가중치 없이) 학습하면 모델이 "모서리", "곡면", "반사광" 같은 기본적인 시각 특징부터 배워야 해서 수만 장이 필요하고, 적은 데이터로는 과적합되어 처음 보는 사진에서 성능이 크게 떨어진다.

둘째, 이미 비슷한 것을 배운 모델이다. COCO에는 bottle(병)과 cup(컵) 클래스가 포함되어 있어, 사전학습 모델은 페트병과 플라스틱 컵의 형태 특징을 어느 정도 알고 있다. 우리는 그 지식 위에 "페트병 / 캔 / 일반쓰레기를 구분하는 법"만 추가로 가르치면 된다.

셋째, 학습 시간과 비용이 줄어든다. 사전학습 모델은 수십 에폭 안에 수렴하는 경우가 많아 Google Colab 무료 GPU로도 충분히 학습할 수 있다.

검증 단계에서 사전학습 효과를 직접 확인하기 위해, 같은 데이터로 가중치 없이 학습한 모델(yolo26n.yaml)도 한 번 학습해 테스트셋 성능을 비교한다(7장 실험 E). 사전학습 모델의 성능이 확실히 높게 나오는 것이 정상이며, 이 결과를 근거 자료로 보고서에 남긴다.

## 5. 데이터 준비

### 5.1 기존 전처리 파이프라인과의 관계

report/preprocess.md의 학습 데이터 정제 단계(1 얼굴 필터, 2 품질 필터, 3 중복 제거, 4 라벨 검수, 5 세션 단위 분할)는 YOLO에서도 그대로 사용한다. `python code/preprocess_code.py build`로 정제와 분할을 마친 뒤, 남은 사진에만 박스 라벨을 그린다. 흐리거나 중복된 사진에 라벨링 시간을 쓰지 않기 위해서다.

모델 입력 처리 단계는 일부가 YOLO 내부로 옮겨간다. 6 ROI 크롭은 그대로 직접 적용한다(학습과 추론 모두). 7 리사이즈와 11 정규화는 Ultralytics가 내부에서 처리하는데, 비율을 유지한 채 회색 여백을 붙여 320×320으로 맞추고(letterbox) 0~1 범위로 나눈다. 따라서 이 두 단계는 직접 하지 않으며, 추론 때도 반드시 Ultralytics의 predict 또는 같은 방식으로 변환된 모델을 써야 학습과 입력이 일치한다. 8 CLAHE는 쓰기로 결정하면 학습과 추론 모두 ROI 크롭 직후에 직접 적용한다. 9 증강과 10 클래스 균형은 5.4절에서 Ultralytics 설정으로 대체한다.

참고로 Ultralytics는 OpenCV로 읽은 BGR 이미지를 그대로 받아 내부에서 처리하므로, 직접 BGR→RGB 변환을 하면 오히려 색이 뒤집힌다. 추론 코드에서 이 부분을 주의한다.

### 5.2 라벨링

라벨링 도구는 Roboflow, CVAT, Label Studio 중 하나를 쓰고 YOLO 형식으로 내보낸다. 라벨 규칙은 다음과 같이 통일한다.

박스는 손을 제외한 쓰레기 부분만 감싸고, 손에 일부 가려진 경우에도 보이는 부분 기준으로 전체 물체를 감싼다. 빨대가 꽂힌 페트병은 페트병 하나로, 플라스틱 컵과 우유팩은 학교 분리배출 기준에 따라 정한 클래스로 라벨링한다(현재 기준: general, 학교 기준 확인 후 확정). 쓰레기가 없는 빈 배경판·손만 있는 사진도 전체의 약 10%를 라벨 없이(빈 라벨 파일) 포함해 오감지를 줄인다. 여러 개를 함께 든 사진은 물체마다 박스를 따로 그린다.

애매한 사진은 기존처럼 _review 폴더로 분리하고 2인 교차 검수 후 확정한다.

### 5.3 데이터 구성 (data.yaml)

```yaml
path: data/yolo
train: images/train
val: images/val
test: images/test
names:
  0: pet
  1: can
  2: general
```

목표 수량은 클래스당 학습용 300장 이상이며, 데이터가 가장 적은 캔은 찌그러진 캔을 포함해 실물을 추가 촬영한다. 여러 개를 함께 든 사진은 전체의 10% 이상 포함한다.

### 5.4 증강 설정 (preprocess.md 9단계 대응)

Ultralytics는 학습 중 자동으로 증강을 적용하며, 현장 조건에 맞춰 아래처럼 조정한다. 색 변화(hsv_h 0.015, hsv_s 0.3, hsv_v 0.3)는 시간대별 조명 차이에 대응한다. 회전(degrees 30)과 상하·좌우 뒤집기(flipud 0.5, fliplr 0.5)는 위에서 찍기 때문에 놓는 방향이 제각각인 상황에 대응한다. 크기 변화(scale 0.3)와 약한 원근(perspective 0.0005)은 거리 차이와 찌그러짐에 대응한다.

모자이크(mosaic)는 사진 4장을 이어 붙여 한 장에 여러 물체가 나오게 하는 증강인데, "여러 개" 상황을 학습하는 데 도움이 되므로 기본값을 유지하고 마지막 10에폭에서만 끈다(close_mosaic 10). albumentations가 설치되어 있으면 블러·CLAHE 등이 낮은 확률로 함께 적용된다.

Ultralytics 검출 학습은 클래스 가중치 옵션이 따로 없으므로, 캔 데이터 부족은 추가 촬영으로 해결하는 것을 원칙으로 한다.

## 6. 학습 방법

학습은 Google Colab(GPU)에서 진행한다.

```bash
pip install ultralytics

yolo detect train model=yolo26n.pt data=data.yaml imgsz=320 \
  epochs=100 patience=20 batch=32 seed=42 \
  hsv_h=0.015 hsv_s=0.3 hsv_v=0.3 degrees=30 flipud=0.5 fliplr=0.5 \
  scale=0.3 perspective=0.0005 close_mosaic=10 \
  project=runs name=y26n_320
```

model=yolo26n.pt가 사전학습 가중치를 불러오는 부분이다. 최대 100에폭을 돌리되, 검증 성능이 20에폭 동안 나아지지 않으면 자동으로 멈추고(patience=20) 가장 좋았던 가중치를 runs/y26n_320/weights/best.pt로 저장한다. seed를 고정해 같은 조건이면 같은 결과가 나오게 한다.

학습 중에는 runs 폴더의 results.png에서 학습 손실과 검증 손실, mAP 곡선을 확인한다. 학습 손실은 계속 내려가는데 검증 손실이 다시 올라가면 과적합이므로 데이터 추가나 증강 강화를 검토한다.

## 7. 검증 방법

검증은 모델이 잘 찾는지 보는 1단계(모델 지표)와, 실제 제품이 올바르게 안내하는지 보는 2단계(제품 지표)로 나눈다. 시험용(test) 데이터는 모든 설정을 끝낸 뒤 마지막에 한 번만 사용한다. 설정을 고를 때마다 시험용 데이터를 보면 그 데이터에 맞춰진 결과가 나와 실제 성능을 과대평가하게 되기 때문이다.

### 7.1 1단계: 모델 지표 (val 데이터)

```bash
yolo detect val model=runs/y26n_320/weights/best.pt data=data.yaml imgsz=320 split=val
```

실행하면 아래 형식의 결과표가 나온다. 숫자는 학습 후 실제 값으로 채운다.

```
Class      Images  Instances  Box(P      R      mAP50  mAP50-95)
all          ___      ___     ___      ___     ___      ___
pet          ___      ___     ___      ___     ___      ___
can          ___      ___     ___      ___     ___      ___
general      ___      ___     ___      ___     ___      ___
```

#### 결과표 항목의 의미

Class 열의 all은 세 클래스의 평균이고, 그 아래 줄이 클래스별 결과다. Images는 검증에 쓴 사진 수(클래스 줄은 그 물체가 들어 있는 사진 수), Instances는 정답 박스 수다. Instances가 적은 클래스는 점수가 우연에 크게 흔들리므로, 데이터가 가장 적은 캔도 검증 데이터에 최소 50개 이상의 박스가 들어가도록 한다.

P(정밀도)는 모델이 찾았다고 한 것 중 맞은 비율이고, R(재현율)은 실제 정답 중 찾아낸 비율이다. 예측 박스는 정답 박스와 겹친 정도(IoU = 겹친 넓이 ÷ 합친 넓이)가 기준 이상이고 클래스가 같아야 맞힘(TP)으로 인정되며, 물체가 없는 곳의 박스, 클래스가 틀린 박스, 같은 물체에 중복으로 친 박스, 겹침이 부족한 박스는 틀림(FP), 찾지 못한 정답은 놓침(FN)으로 채점된다.

mAP50은 IoU 0.5 기준으로 클래스별 AP(정밀도-재현율 곡선 아래 넓이)를 평균한 값이고, mAP50-95는 IoU 기준을 0.5부터 0.95까지 10단계로 엄격하게 바꿔가며 구한 값의 평균이다. 검증(val) 때는 신뢰도 기준을 0.001처럼 거의 0으로 두고 곡선 전체를 계산한다.

#### 이 제품에서 중요하게 볼 지표

이 제품은 박스를 정밀하게 그릴 필요가 없고, 어떤 쓰레기인지와 몇 개인지만 맞으면 된다. 따라서 박스 위치의 정밀도까지 따지는 mAP50-95보다 **mAP50과 클래스별 P·R**을 주요 지표로 보고, mAP50-95는 참고 지표로만 기록한다.

또 결과표의 P·R은 신뢰도 기준을 거의 0으로 두고 계산한 값이라, 실제 제품이 쓰는 신뢰도 0.7에서의 성능과 다르다. 신뢰도 기준을 올리면 정밀도는 오르고 재현율은 내려가는 시소 관계가 있으므로, F1_curve.png와 PR_curve.png에서 0.7 부근의 P·R을 따로 확인하고, F1이 가장 높은 기준값과 비교해 PRD의 0.7이 적절한지 검증한다. 기준을 바꿀 경우 이 val 결과를 근거로 바꾸고 PRD에 반영한다.

함께 생성되는 confusion_matrix.png로 어떤 클래스끼리 헷갈리는지 확인한다. 현장 조사 기준으로 예상되는 혼동은 페트병과 플라스틱 컵(general), 캔과 은박 과자 봉지(general)다.

중복 검출도 따로 확인한다. 같은 물체에 박스가 두 개 잡히면 제품에서는 "여러 개"로 잘못 판단해 불필요한 재시도 안내가 나간다. YOLO26은 NMS 없이 물체당 하나의 박스를 내도록 설계되어 이 문제가 줄어들 것으로 기대하지만, 검증 데이터의 예측 결과에서 한 물체에 박스가 두 개 이상 잡힌 사례 수를 세어 확인한다.

#### 결과 진단 기준과 대응

결과표를 보고 아래 기준으로 원인을 판단하고 조치한다.

P는 높고 R이 낮으면 모델이 확실한 것만 답하고 많이 놓치는 상태다. 이 제품에서는 재시도 안내가 잦아지는 형태로 나타난다. 신뢰도 기준을 낮춰보고, 놓친 유형(예: 손에 많이 가려진 캔, 납작하게 찌그러진 페트병)의 사진을 추가한다.

P는 낮고 R이 높으면 헛탐지가 많은 상태다. 이 제품에서는 빈 배경판이나 손만 보여도 박스가 잡혀 오감지 개방이 늘어난다. 신뢰도 기준을 올리고, 물체가 없는 배경판·손만 있는 사진(빈 라벨)을 추가한다. 특정 클래스만 P가 낮다면 헷갈리는 물체 쪽 사진을 늘린다. 예를 들어 캔의 P가 낮으면 은박 봉지를 general로 라벨링한 사진을 추가한다.

mAP50은 높은데 mAP50-95만 낮으면 물체는 찾지만 박스가 대충인 상태다. 이 제품은 박스 정밀도가 크게 중요하지 않으므로 우선순위를 낮추되, 손 포함 여부 등 라벨 박스 기준이 사람마다 달랐는지 점검한다.

모든 지표가 낮으면 아직 덜 배운 상태다. 에폭 수를 늘리고(patience 확대), 데이터 양과 라벨 품질(잘못 붙은 클래스, 빠진 박스)을 점검한다.

### 7.2 2단계: 제품 지표 (test 데이터, 최종 1회)

PRD의 KPI는 박스 정확도가 아니라 "올바른 투입구를 안내했는가"이므로, 시험용 사진마다 실제 제품과 같은 후처리 규칙을 적용해 최종 판단을 내리고 정답과 비교한다. 규칙은 다음과 같다. 박스가 없으면 "물체 없음", 신뢰도 0.7 이상 박스가 2개 이상이면 "여러 개(하나씩 보여주세요)", 1개면 그 클래스로 안내, 0.7 미만 박스만 있으면 "재시도"로 판정한다.

이 결과로 다음을 계산한다. 전체 안내 정확도 90% 이상과 클래스별 최저 85% 이상(재시도 판정은 오답이 아닌 별도 비율로 집계하고 15% 이하 목표), 빈 화면 사진에서 박스가 잡힌 비율인 오감지율 1% 이하, 여러 개 사진을 "여러 개"로 판정한 비율 90% 이상(가정 목표)이다.

### 7.3 Raspberry Pi 실측

```bash
yolo export model=runs/y26n_320/weights/best.pt format=ncnn imgsz=320
```

Ultralytics 문서는 Raspberry Pi에서 NCNN 형식이 가장 빠른 편이라고 안내하고 있어 NCNN을 우선 사용하고, 비교용으로 TFLite INT8도 변환한다. 변환한 모델로 test 데이터 검증을 다시 실행해 정확도 하락이 2%p 이하인지 확인한다.

Pi 4에서는 실제 카메라를 연결해 감지 신호부터 LED 점등까지 100회 측정하고 평균과 95백분위를 기록한다. 목표는 95백분위 2초 이내, 평균 1초 이내다.

### 7.4 비교 실험 계획

최종 모델 결정을 위해 같은 데이터로 다음 실험을 진행한다.

실험 A는 YOLO26n 검출, 사전학습, 입력 320으로 기본안이다. 실험 B는 같은 조건에서 입력 416으로, 정확도가 오르는 만큼 속도가 감당되는지 본다. 실험 C는 YOLO26s 검출, 입력 320으로 모델 크기를 키웠을 때를 본다. 실험 D는 YOLO11n 검출, 입력 320으로 이전 세대와 비교한다. 실험 E는 YOLO26n을 사전학습 없이(yolo26n.yaml) 학습해 사전학습 효과를 확인한다. 실험 F는 YOLO26n-cls 분류 모델(4클래스)로, 검출 방식을 고른 판단이 맞는지 확인한다.

선정 기준은 순서대로 제품 KPI 충족(정확도 90%, 클래스별 85%), Pi 4의 95백분위 응답 시간 2초 이내, 모델 파일 10MB 이하, 여러 개 판정 가능 여부다. 기준을 모두 만족하는 후보 중 가장 빠른 모델을 최종 선정한다.

## 9. 후속 작업

PRD v0.3의 기술 스택에서 AI 모델을 MobileNetV3에서 YOLO26n 검출로 바꾸고, 라이선스(AGPL-3.0, 상용화 시 별도 라이선스) 내용을 반영한다. 클래스 정의도 "4클래스(물체 없음 포함)"에서 "3클래스 + 박스 없음"으로 수정한다.

code/preprocess_code.py의 train과 infer 명령을 Ultralytics YOLO 기반으로 바꾼다. build(정제·분할)는 그대로 쓰고, 추론에서는 "여러 개" 판정 시 Arduino로 재시도 신호를 보내도록 후처리 규칙을 추가한다.

report/preprocess.md에는 7 리사이즈와 11 정규화가 Ultralytics 내부 처리(letterbox, 0~1 정규화)로 바뀌었다는 점과, 추론 시 BGR→RGB 변환을 하지 않는다는 점을 추가한다.
