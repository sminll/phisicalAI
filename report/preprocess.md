# 데이터 전처리 보고서 — AI 분리수거 도우미 스마트 쓰레기통

- 대상: 페트병 / 캔 / 일반쓰레기 / 물체 없음 분류 (MobileNetV3, 224×224)
- 환경: 본관 2층 복도 매점 옆, 창가 / USB 웹캠 720p 상단 하향 촬영 / Raspberry Pi 4
- 근거 자료: 현장 조사 S-01 (괄호 안 번호는 체크리스트 항목 번호)

## 전처리 파이프라인 요약

```
[학습] 얼굴 필터 → 품질 필터 → 중복 제거 → 라벨 검수 → 데이터 분할
       → ROI 크롭 → 리사이즈 → (CLAHE) → 데이터 증강 → 클래스 균형 → 정규화 → 학습

[추론] 초음파 감지 → 5프레임 촬영 → 최선 프레임 선택 → BGR→RGB
       → ROI 크롭 → 리사이즈 → (CLAHE) → 정규화 → 추론 → 프레임 즉시 폐기
```

> 전제 조건 (하드웨어): 카메라 자동 노출·자동 WB 끄기(4-1), 인식 영역 차광 후드 + 확산 LED 조명(1-4, 1-5), 무광 배경판(2-3).
> 조명 변화는 전처리보다 하드웨어 고정이 훨씬 효과적이므로 아래 전처리는 이 조건을 갖춘 상태를 기준으로 한다.

## 기법 · 적용 이유 · 추천 파라미터

1. 얼굴 필터
   - 적용 이유: 상단 촬영이라 얼굴이 찍히는 일은 드물지만(2-5), 학습용 사진을 저장하는 동안 프라이버시 안전망이 필요합니다(5-5).
   - 추천 파라미터: OpenCV DNN 얼굴 검출(res10 SSD)로 신뢰도 0.5 이상이면 삭제합니다.

2. 품질 필터
   - 적용 이유: 쓰레기를 던지듯 빠르게 보여줘서 흐린 사진이 생기고(3-6), 오후 역광에 노출이 날아가며(1-4), 음료 튐·손자국으로 렌즈가 오염됩니다(4-3).
   - 추천 파라미터: Laplacian 분산 100 미만은 제외하되 예비 촬영 40장으로 기준을 보정합니다. 밝기(V) 평균이 40 미만이거나 220 초과, 또는 포화 픽셀이 5%를 넘으면 제외합니다.

3. 중복 제거
   - 적용 이유: 센서 감지 후 연속 촬영하기 때문에 거의 같은 사진이 여러 장 생깁니다(4-2).
   - 추천 파라미터: pHash 해밍 거리 5 이하이면 중복으로 보고 한 장만 남깁니다.

4. 라벨 검수
   - 적용 이유: 플라스틱 컵, 빨대 꽂힌 페트병, 우유팩처럼 어느 클래스인지 헷갈리는 사례가 많습니다(3-3, 3-4).
   - 추천 파라미터: 경계 사례는 별도 폴더로 분리해 2인이 교차 검수하고, 학교 분리배출 기준에 맞춘 라벨 규칙을 문서로 정리합니다.

5. 데이터 분할
   - 적용 이유: 시간대별 밝기 차이가 커서(1-5), 같은 세션 사진이 학습셋과 테스트셋에 섞이면 정확도가 부풀려집니다.
   - 추천 파라미터: 날짜·시간대 세션 단위로 학습 70 / 검증 15 / 테스트 15로 나눕니다.

6. ROI 크롭
   - 적용 이유: 쓰레기통 본체 일부가 함께 찍히고(2-5), 실제로 필요한 건 배경판 영역뿐입니다(2-3).
   - 추천 파라미터: 1280×720 원본 중 배경판이 있는 720×720 정사각 영역을 고정 좌표로 자릅니다.

7. 리사이즈
   - 적용 이유: Raspberry Pi 4에서 2초 이내에 추론을 끝내야 합니다(4-4).
   - 추천 파라미터: 224×224, 축소에 유리한 INTER_AREA 보간을 사용합니다.

8. CLAHE (선택)
   - 적용 이유: 형광등과 창문 자연광이 섞여(1-2) 하드웨어 고정 후에도 밝기 편차가 남을 수 있습니다.
   - 추천 파라미터: LAB의 L 채널에 clipLimit 2.0, 8×8 타일로 적용합니다. 적용/미적용 두 버전을 학습해 검증 정확도가 높은 쪽으로 결정합니다.

9. 데이터 증강
   - 적용 이유: 시간대별 조명 변화(1-5), 찌그러진 페트병·캔(3-1, 3-2), 손에 가려짐(2-5), 빠른 동작(3-6)에 모델이 견디도록 합니다. 위에서 찍기 때문에 놓이는 방향도 제각각입니다.
   - 추천 파라미터: 밝기·대비 ±0.3, 감마 70~150, Hue ±8과 채도·명도 ±25, 그림자 확률 0.3, 90° 단위 회전에 ±30° 추가 회전, 원근 변환 0.02~0.05, 모션 블러 커널 3~9(확률 0.3), Coarse Dropout으로 면적 10~15% 가리기.

10. 클래스 균형
   - 적용 이유: 캔이 전체의 15%로 가장 적어(3-5) 클래스별 최저 85% 기준을 못 넘길 위험이 큽니다.
   - 추천 파라미터: 클래스 가중치를 빈도의 역수로 주고, 찌그러진 캔을 포함한 캔 실물 사진을 300장 이상 추가로 촬영합니다.

11. 정규화
   - 적용 이유: 사전학습된 MobileNetV3(5-2)가 기대하는 입력 분포와 맞춰야 합니다.
   - 추천 파라미터: Keras 내장 전처리 층을 쓰면 0~255 값을 그대로 넣고, 따로 정규화한다면 /255 또는 ImageNet 평균·표준편차를 씁니다. 어느 쪽이든 학습과 추론에서 똑같이 적용합니다.

## 순서의 핵심 근거

1이 맨 앞: 얼굴이 담긴 이미지는 복사·가공되기 전에 제거해야 프라이버시 위험이 다른 단계로 퍼지지 않습니다.

2→3: 흐린 사진을 먼저 버려야 중복 제거 시 비슷한 사진 묶음에서 선명한 사진이 남습니다.

3→4→5: 중복을 제거하고 라벨을 확정한 뒤 분할해야, 거의 같은 사진이 학습셋과 테스트셋에 나뉘어 들어가는 데이터 누수를 막고 클래스 비율에 맞춰 나눌 수 있습니다.

6→7: 720p 원본에서 필요한 영역을 먼저 잘라야 리사이즈로 인한 해상도 손실이 최소화됩니다.

8→9: CLAHE는 항상 같은 결과를 내는 보정이라 추론과 동일하게 먼저 적용하고, 증강은 그 위에 무작위 변동을 더합니다. 순서를 바꾸면 CLAHE가 증강으로 만든 밝기 변화를 상쇄해버립니다.

9·10은 5 이후 학습셋에만: 검증·테스트셋에 증강이나 오버샘플링이 들어가면 실제 성능을 측정할 수 없습니다.

11이 마지막: 증강은 0~255 정수 이미지 기준으로 동작하므로, 정규화를 먼저 하면 증강 연산의 값 범위가 깨집니다.

6·7·8·11은 추론에서도 똑같이 적용해야 학습과 실제 입력 분포가 일치합니다. 1·3·4·5·9·10은 학습 전용입니다.

## 추론 시 (Raspberry Pi 4)

초음파 감지(4-2) → 버퍼에 남은 프레임 버리기 → 5프레임 연속 촬영 → 2의 Laplacian 기준으로 가장 선명한 프레임 선택(기준 미달 시 "다시 보여주세요") → BGR→RGB 변환 → 6 → 7 → 8(학습에 사용한 경우만) → 11 → 추론 → 신뢰도 0.7 미만이면 최대 2회 재시도, 이후 일반쓰레기 안내 → 프레임은 메모리에서 즉시 폐기하고 결과 텍스트만 로그 기록.

얼굴 필터는 상단 촬영으로 얼굴이 거의 들어오지 않고 프레임을 저장하지 않으므로 추론에서는 생략하며, 손만 보이거나 빈 화면은 "물체 없음" 클래스가 처리합니다. 카메라 스트림은 항상 열어두어 매번 여는 지연(1초 이상)을 피하고, 5프레임 촬영 약 0.2초 + 전처리·추론 수백 ms 이내로 2초 목표를 확보합니다.

> 참고: 2~3개를 한꺼번에 보여주는 경우가 관찰되었으므로(3-6), 이미지 분류 방식에서는 "여러 개" 클래스 추가 또는 YOLOv8n 검출 방식 전환을 검토해야 PRD의 "하나씩 보여주세요" 예외 처리가 가능합니다.
