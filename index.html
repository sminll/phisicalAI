01 · 문제 정의

분리수거함은 있는데, 왜 잘못 버려질까요?

사용자가 쓰레기 종류와 배출 기준을 직접 판단해야 하기 때문입니다. 기준을 모르거나 급할 때는 아무 칸에나 버리게 되고, 그 부담은 관리자와 환경으로 이어집니다.

사용자

기준을 모름

라벨 붙은 페트병, 종이컵, 은박 포장재처럼 헷갈리는 쓰레기가 많아 잘못된 칸에 투입합니다.

사용자

판단이 귀찮음

쉬는 시간처럼 바쁜 순간에는 고민할 여유가 없어 "일단 일반쓰레기"로 버리는 습관이 생깁니다.

관리자

재선별 부담

혼입된 재활용품을 다시 골라내야 해서 선별 인력과 시간이 계속 늘어납니다.

환경

재활용률 저하

잘못 섞인 페트병과 캔은 재활용되지 못하고 소각·매립되어 자원이 낭비됩니다.

문제 가설

쓰레기를 버리는 그 순간에 무엇을 어디에 버려야 하는지 즉시 알려주면, 사용자는 별도의 학습 없이도 올바르게 분리배출할 것이다.

02 · 작동 방식

보여주기만 하면, 2초 안에 안내합니다

물체 감지부터 투입까지, 사용자는 아무 버튼도 누르지 않습니다.

  1. 1

    물체 감지

    근접 센서가 카메라 앞의 쓰레기를 감지합니다.

  2. 2

    촬영

    USB 카메라가 쓰레기 이미지를 촬영합니다.

  3. 3

    AI 추론

    경량 모델이 종류와 신뢰도를 산출합니다.

  4. 4

    LED · 뚜껑 안내

    올바른 투입구의 LED가 켜지고 뚜껑이 열립니다.

  5. 5

    투입 완료

    5초 후 뚜껑이 닫히고 대기 상태로 돌아갑니다.

시스템 구성

INPUT USB 카메라 720p 웹캠 · 초음파 센서
AI · PYTHON Raspberry Pi 4 YOLO26n 검출 · NCNN
CONTROL · SERIAL Arduino Uno LED · 서보 제어 펌웨어

예외 처리 신뢰도 0.7 미만이면 노란 LED로 재시도를 안내하고, 2회 실패 시 일반쓰레기 투입구를 안내합니다.

03 · 데이터 처리

AI가 보기 전에 다듬고, 본 뒤에 한 번 더 확인합니다

설치 후보 장소(본관 2층 매점 옆 창가)를 현장 조사해 보니 오후 역광, 늘 함께 찍히는 손, 부족한 캔 데이터가 정확도를 위협했습니다. 그래서 사진을 모델에 넣기 전의 전처리 11단계와, 모델의 답을 그대로 믿지 않는 후처리 판단 규칙을 설계했습니다.

학습 학습할 때만 공통 학습과 실시간 추론에 같은 코드로 적용

    후처리: 모델의 답을 바로 믿지 않습니다

    추론이 끝나면 판단 규칙을 위에서부터 차례로 확인합니다. 걸리는 항목이 있으면 노란 LED로 다시 보여달라고 안내하고, 최대 2번까지 다시 찍습니다.

    실시간 처리 순서

    1. 초음파 센서가 물체 접근을 감지
    2. 카메라에 남은 오래된 프레임 3장을 버림
    3. 5장을 연속 촬영해 가장 선명한 1장만 선택
    4. ROI 크롭 후 YOLO26n으로 쓰레기 위치와 종류를 검출
    5. 원본 사진은 즉시 메모리에서 삭제
    6. 판단 규칙 적용 후 결과만 텍스트로 기록
    1. 1
      아무것도 잡히지 않았나요?

      박스가 0개면 지나가는 사람에게 센서가 반응한 경우입니다. 다시 찍고, 3번 모두 비어 있으면 뚜껑을 열지 않습니다.

      취소
    2. 2
      2개 이상 잡혔나요?

      친구 것까지 한꺼번에 들고 오는 경우입니다. 칸이 서로 다를 수 있으니 하나씩 보여달라고 안내합니다.

      하나씩 보여주세요
    3. 3
      흔들려서 흐린가요?

      쓰레기를 던지듯 보여주면 선명도가 기준 미만으로 떨어집니다. 흐린 사진의 답은 쓰지 않습니다.

      다시 보여주세요
    4. 4
      신뢰도가 0.7보다 낮은가요?

      플라스틱 컵, 은박 봉지처럼 헷갈리는 물체에서 자주 생깁니다. 확신이 없으면 다시 확인합니다.

      다시 보여주세요
    5. ✓

    04 · AI 모델

    수많은 YOLO 중에 YOLO26n을 고른 이유

    YOLO는 버전, 크기, 작업 종류로 나뉘고, 모델 이름에 세 가지가 모두 들어 있습니다. 라즈베리파이에서 2초 안에 답하고, 여러 개를 한꺼번에 보여줘도 구분할 수 있는 조합을 골랐습니다.

    yolo26n

    버전 26
    Ultralytics의 최신 세대입니다. 겹친 박스를 지우는 후처리(NMS) 없이 물체당 박스 하나를 내고, 작은 장치의 CPU에서 빠르게 돌도록 설계됐습니다.
    크기 n (nano)
    5단계 중 가장 작고 빠른 모델입니다. GPU가 없는 라즈베리파이 4에서도 2초 목표를 맞출 수 있습니다.
    작업: 검출 (빈칸)
    이름 끝에 아무것도 없으면 물체마다 박스를 치는 검출용입니다. -cls는 분류, -seg는 분할, -pose는 자세 추정입니다.

    크기 5단계 비교

    눌러서 비교해 보세요. 클수록 정확하지만 느려집니다.

    상대 비교입니다. 실제 수치는 Ultralytics 공식 문서와 라즈베리파이 실측으로 확인합니다.

    왜 분류가 아니라 검출인가

    현장 조사에서 쓰레기 2~3개를 한꺼번에 보여주는 경우가 15분에 5번 있었습니다.

    처음부터 가르치지 않고, 사전학습 모델에서 시작합니다

    COCO 데이터셋으로 미리 학습된 yolo26n.pt에서 출발해, 우리 쓰레기 사진으로 다시 학습하는 전이학습 방식입니다.

    • 데이터가 적습니다클래스당 수백 장으로는 모서리·곡면·반사광 같은 기본 특징부터 배울 수 없어 과적합됩니다.
    • 이미 병과 컵을 압니다COCO에 bottle, cup이 있어 페트병과 플라스틱 컵의 모양을 어느 정도 알고 시작합니다.
    • 무료 GPU로 충분합니다수십 에폭 안에 수렴해 Google Colab에서 학습할 수 있습니다. 사전학습 없이 학습한 모델과도 비교해 효과를 확인합니다.

    학습과 검증 순서

    1. 정제 · 분할얼굴·흐림·중복 제거, 날짜·시간대 단위로 학습/검증/시험 분할
    2. 박스 라벨링pet · can · general 3종, 손 제외하고 쓰레기만. 빈 배경 사진 10% 포함
    3. Colab 학습입력 320, 최대 100에폭, 20에폭 동안 개선 없으면 자동 종료
    4. 결과표 해석검증 데이터로 mAP50과 클래스별 정밀도·재현율 확인
    5. 제품 기준 시험시험 데이터에 실제 판단 규칙을 적용해 안내 정확도 계산 (마지막 1회)
    6. 라즈베리파이 실측NCNN으로 변환 후 정확도 하락과 응답 시간 100회 측정
    yolo detect train model=yolo26n.pt data=data.yaml imgsz=320 epochs=100 patience=20 \
  hsv_s=0.3 hsv_v=0.3 degrees=30 flipud=0.5 fliplr=0.5 scale=0.3 close_mosaic=10

    합격 기준

    아래 기준을 모두 넘어야 모델을 확정합니다. 넘지 못하면 아래 진단표로 원인을 찾아 고친 뒤 다시 학습합니다.

    • 90%이상전체 안내 정확도시험 데이터에 실제 판단 규칙 적용
    • 85%이상클래스별 최저 정확도데이터가 가장 적은 캔 포함
    • 2초이내감지부터 안내까지라즈베리파이 100회 측정, 95백분위
    • 1%이하빈 화면 오감지쓰레기 없이 뚜껑이 열린 비율
    • 2%p이내변환 후 정확도 하락NCNN 변환 전후 비교
    • 10MB이하모델 파일 크기라즈베리파이 저장·실행 조건

    정밀도(P) 찾았다고 한 것 중 맞은 비율 · 재현율(R) 실제 쓰레기 중 찾아낸 비율 · mAP50 박스가 절반 이상 겹치면 정답으로 보고 낸 평균 점수. 이 제품은 박스를 정밀하게 그릴 필요 없이 종류와 개수만 맞으면 되므로 mAP50과 클래스별 P·R을 주요 지표로 보고, mAP50-95는 참고로만 기록합니다. 결과표는 신뢰도 기준을 거의 0으로 두고 계산하므로, 실제 제품이 쓰는 0.7에서의 P·R은 따로 확인합니다.

    결과에 따른 진단과 조치

    • P 높음 · R 낮음 확실한 것만 답하고 많이 놓침

      재시도 안내가 잦아집니다. 신뢰도 기준을 낮춰보고, 손에 가려진 캔처럼 놓친 유형의 사진을 추가합니다.

    • P 낮음 · R 높음 헛탐지가 많음

      빈 배경에도 뚜껑이 열립니다. 기준을 올리고 빈 배경·손만 있는 사진을 추가합니다. 캔만 낮으면 은박 봉지 사진을 늘립니다.

    • mAP50 높음 · 50-95 낮음 찾긴 하는데 박스가 대충

      이 제품엔 영향이 작습니다. 손 포함 여부처럼 라벨 기준이 사람마다 달랐는지만 점검합니다.

    • 전부 낮음 아직 덜 배움

      에폭을 늘리고, 데이터 양과 잘못 붙은 라벨을 점검합니다.

    라이선스 Ultralytics YOLO는 AGPL-3.0입니다. 학교 프로젝트로 코드를 공개해 쓰는 것은 문제없지만, 제품으로 판매하려면 별도 라이선스가 필요합니다.
